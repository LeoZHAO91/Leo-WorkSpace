怎么用 · 加内容与开会

三个入口 · 六步会议
① 你想干的内容，从哪进
  1. 本页顶部「智能投放」（今日工作视图）：写一句复合意图 → 自动拆到 待办 / 日历 / 节点 / 邮件
  2. 直接对小雷欧说：最省事，任何想法直接讲
  3. 议题收件箱：按模板写成文件放进 leo-ai-company/agenda/
注意：本页的 AI 是独立通道，与 WorkBuddy 里的 Agent 团队不互通——在网页里写的内容不会自动触发下面的会议。
② 让他们开会（六步）
  1. 立题：给议题 + 口径 / 时间 / 区域
  2. 定人：COO 按议题选派参会 Agent，够用即可
  3. 独立表态：各 Agent 互相看不到对方，防趋同
  4. 汇总：共识 / 真分歧 / 口径冲突 / 矛盾排查
  5. 表决（可选，仅明确取舍时）
  6. 落盘：纪要写入 meetings/ 并回报摘要
三个必须知道的边界

1. 同源模型：5 个 Agent 跑在同一底层模型上，角色差异来自提示词——纪要里的"共识"不等于多方独立验证。
2. 表决不是证据：投票只用来呈现"不同优先级下会怎么选"，不能当成可靠性背书。
3. 无数据不推演：缺数据处标注"待确认"并给出获取路径，不会为了把会开完整而编造。

纪要固定十段，核心是「各方立场（关键人员发言）」与「分歧清单」——最该看的往往不是结论， 而是哪几个职能在哪一点上不一致、依据是什么、还缺什么证据才能收敛。

管理层复核 · 必须检查

  1. 哪些是事实
  2. 哪些是推导
  3. 哪些是假设
  4. 时间、单位、币种、统计口径是否一致
  5. 不同 Agent 是否存在矛盾
  6. 核心经营问题是什么
  7. 最大风险是什么
  8. 最大机会是什么
  9. 最终需要什么动作

默认最终输出格式

  1. 结论
  2. 关键数据
  3. 核心问题
  4. 原因
  5. 风险与机会
  6. 建议动作
  7. 负责人 / 时间节点
  8. 待确认事项

统一分析原则

全体 Agent 共同遵守
  • 目标和前提优先
  • 检查数据完整性
  • 不迎合预设结论
  • 区分事实、推导、判断、建议
  • 核对口径、单位和时间范围
  • 结论先行
  • 问题 → 原因 → 动作 → 负责人
  • 重点关注目标完成率、同比、差距、风险和机会
  • 异常数据必须回答“为什么”和“怎么办”
权限原则：专业 Subagent 主要负责分析，不负责最终跨部门结论；Leo COO 负责最终综合和输出。尽量只给每个 Subagent 必要的工具权限。
